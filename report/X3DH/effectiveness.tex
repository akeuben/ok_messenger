As X3DH involves the use of a server, Alice or Bob can retrieve the other parties public key bundle without them needing to be online. This allows for asynchronous key exchanges to take place, which enables either party to initialize the root key chain and start communication even if the recipient is offline. As regular Diffie-Hellman and ECDH algorithms don't involve a server and both parties need to be online to exchange their public keys, this functionality is unique to X3DH.

When a new user logs into our messenging app, they generate a long-term identity key (with a corresponding private identity key) and are required to use this to sign a prekey. Both of these keys are used during the X3DH key exchange, and these keys enable the users to mutually authenticate each other as only a unique identity/signed prekey pair will provide a certain DH output.
